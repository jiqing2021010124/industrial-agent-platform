## 1. 客户场景与需求分析

### 1.1 某磷化工企业 — 磷化工流程制造

**企业概况**：国内磷化工龙头，正在建设某磷化工基地智慧工厂全球样板点，已挂牌贵州首个国家级"磷化工制造业数字化转型促进中心"。

**已有数字化基础**：
- 携手华为打通 **30 个应用系统**，全量 **700 万条业务数据 + 15,339 个设备数据 + 16 万条主数据** 入湖
- 数据使用成本降低 50%
- 完成园区 + 7 个装置 + 17 个项目的数字孪生
- 部署 F5G 全光网络 + 5G 专网 + 华为数字平台

**核心工艺痛点**：

| 痛点 | 现状 | 目标 |
|------|------|------|
| **数据孤岛** | 30 个系统割裂，跨系统协同困难 | 全链路数据贯通 |
| **设备管理复杂** | 15,000+ 设备分散管理，缺乏统一监控 | 设备健康度统一画像 |
| **氯碱装置电压预测** | 总槽电压缺乏长周期预测，碳酸钠加入量凭经验 | AI 预测 + 优化建议（年省百万级） |
| **重大危险源风险** | 9 处重大危险源风险识别依赖人工 | AI 风险识别 + 责任追溯闭环 |
| **磷石膏资源化** | "三高"问题（高能耗/高污染/高资源消耗），能源利用率 <40% | 能耗降低 15%+，环保达标率 99%+ |
| **黄磷生产配料** | 凭肉眼判断反应釜色泽，凭手感调阀门 | 算法动态调整原料配比 |

### 1.2 某电解铝企业 — 电解铝流程制造

**企业概况**：国内首个落地电解铝复杂体系动态优化预测大模型的企业，已实现 56 台电解槽 AI 调控，计划扩展至 500 台。

**已有数字化成果**：
- 电解铝大模型每天 7:00 自动分析，7:05 下达指令至槽控设备
- 参数误差控制在 0.2 以内，吨铝电耗降低 100+ 度
- 56 台电解槽年省电费 180 万元，500 台全面覆盖预计年省 4000 万元
- 氧化铝蒸发工序蒸气消耗降低 3%（年创效 400 万元）
- 焙烧炉天然气单耗每吨下降 3 立方米

**核心工艺痛点**：

| 痛点 | 现状 | 目标 |
|------|------|------|
| **氟化铝添加** | 凭工人个人经验，缺乏科学精准度 | AI 精准下料，误差 <0.2 |
| **出铝计划** | 人工估算，容易偏差 | 模型预测 + 自动排产 |
| **能耗波动** | 时高时低，无法稳定控制 | 波动锁定在极窄区间 |
| **单工序控制** | 各工序独立优化，缺乏全流程协同 | 单工序 → 全流程智能协同 |
| **大模型集中式部署** | 依赖云端/中心算力，实时性受限 | 边缘本地推理，秒级响应 |

### 1.3 流程制造的共性需求总结

基于两家企业的分析，流程制造对云边端智能体平台有 **六项共性需求**：

| 需求维度 | 具体要求 | ClawChips 对应能力 |
|----------|----------|---------------------|
| **实时控制** | 工艺参数毫秒~秒级响应，不能依赖云端往返 | 边缘 NPU 本地推理 |
| **模型协同** | 大模型（复杂决策）+ 小模型（实时控制）协同 | ModelHub 多模型调度 |
| **成本优化** | 高频简单任务本地化，低频复杂任务上云 | 端云智能路由 |
| **数据安全** | 工艺参数、生产数据不出厂区 | 本地 RAG + 边缘推理 |
| **多场景复用** | 质检/运维/调度/安全等场景化技能可插拔 | SKILL 技能集架构 |
| **稳定兜底** | 本地模型超限时自动转云端，不崩溃 | Token 安全网机制 |

## 2. 总体架构设计

### 2.1 设计原则

参考 ClawChips 的核心设计理念，结合流程制造特点，确立五项设计原则：

1. **模型服务与业务逻辑解耦**：上层应用不关心模型部署位置与资源状态
2. **云边端分层协同**：边缘管实时推理，云端管训练管理，端侧管数据采集
3. **安全合规前置**：IT/OT 隔离，只读采集，建议值回写审批
4. **场景先行落地**：从高价值场景切入，逐步沉淀共性能力
5. **AI 不替代 L1 控制**：智能体输出建议值，安全联锁永远属于硬实时系统

### 3.3 资源感知调度策略

工业场景的调度需考虑**实时性优先级**，扩展 ClawChips 的调度逻辑：

```python
class IndustrialModelHub:
    """工业 ModelHub 调度器，扩展自 ClawChips ModelHub"""

    def schedule(self, task):
        # 1. 实时性分级
        priority = self.get_priority(task)
        # P0: 实时控制类（氟化铝下料、氯碱电压调控）—— 强制本地，不可排队
        # P1: 实时监测类（槽况诊断、设备振动监测）—— 优先本地
        # P2: 分析决策类（配料优化、出铝计划）—— 可本地可云端
        # P3: 离线分析类（长周期趋势、模型训练）—— 转云端

        if priority == "P0":
            return self.dispatch_local_immediate(task)
        elif priority == "P1":
            return self.dispatch_local_queued(task)
        elif priority == "P2":
            return self.router.route(task)  # 交由端云智能路由决策
        else:
            return self.dispatch_cloud(task)

    def check_resource(self, task, device):
        """资源安全网：检查设备是否装得下"""
        model = self.registry.get(task.model_name)
        if device.available_vram_mb < model.vram_mb:
            return False, "VRAM不足"
        if device.current_concurrency >= device.max_concurrency:
            return False, "并发已满"
        return True, "OK"
```

## 4. 端云智能路由的工业适配

### 4.1 工业路由决策因子扩展

ClawChips 原始路由仅基于任务复杂度（token 数），工业场景需扩展多维决策因子：

| 决策因子 | 说明 | 路由影响 |
|----------|------|----------|
| **任务复杂度** | 简单推理 vs 复杂规划 | 简单→本地，复杂→云端 |
| **实时性要求** | 毫秒级 vs 分钟级 | 高实时→本地 |
| **数据敏感性** | 公开数据 vs 核心工艺参数 | 敏感→本地（强制） |
| **上下文长度** | token 数是否超本地模型窗口 | 超限→安全网转云端 |
| **设备负载** | 边缘节点当前算力占用 | 过载→云端或排队 |
| **网络状态** | 云端连通性 + 延迟 | 断网→强制本地降级 |
| **工艺安全等级** | 是否涉及安全联锁 | 涉及安全→本地+人工确认 |

### 4.2 工业路由配置示例

```yaml
# ~/.industrial/router.yaml
router:
  strategy: hybrid  # 规则 + 记忆混合
  enable: true

  # 安全约束（最高优先级）
  safety_rules:
    - data_sensitivity: ["core_process_params", "secret_formula"]
      action: LOCAL_ONLY  # 核心工艺参数强制本地
    - safety_interlock: true
      action: LOCAL_ONLY + HUMAN_CONFIRM  # 安全联锁需人工确认

  # 业务路由规则
  business_rules:
    - task_type: "real_time_control"
      latency_ms: 500
      route: LOCAL
    - task_type: "quality_inspection"
      route: LOCAL
    - task_type: "process_optimization"
      complexity: "low"
      route: LOCAL
    - task_type: "process_optimization"
      complexity: "high"
      route: CLOUD
    - task_type: "long_term_analysis"
      route: CLOUD
    - task_type: "knowledge_qa"
      route: LOCAL  # 本地 RAG，数据不出端
    - default: CLOUD

  # 记忆路由配置
  memory:
    enable: true
    feedback_loop: true  # 人工反馈标注
    optimization_cycle: "weekly"  # 每周优化路由策略

  # 安全网配置
  safety_net:
    token_limit: 4096          # 本地模型 token 上限
    memory_limit_mb: 2048      # 内存上限
    latency_limit_ms: 2000     # 延迟上限
    fallback: CLOUD            # 超限自动转云端
    network_check: true        # 断网检测
    degrade_strategy: "lightweight_model"  # 断网时降级为轻量模型
```

### 4.3 多层安全网机制

### 8.2 数据安全策略

| 数据类别 | 安全等级 | 处理策略 |
|----------|----------|----------|

## 11. 总结

本方案以 airockchip/clawchips 为参考架构，针对某磷化工企业（磷化工）和某电解铝企业（电解铝）的流程制造特点，构建了云边端协同工业智能体平台。核心要点：

1. **架构借鉴**：复用 ClawChips 的 ModelHub 调度网关、端云智能路由、Token 安全网三层核心机制，扩展为工业级多层安全网（Token + 内存 + 网络 + 工艺安全）

2. **场景适配**：针对磷化工（氯碱电压预测、危险源识别、磷石膏资源化、黄磷配料）和电解铝（氟化铝下料、槽况诊断、出铝排产、蒸发协同）设计了 8 个落地方案

3. **安全合规**：严格遵循 IT/OT 融合安全约束，AI 平台定位为 L2~L4 能力增强层，绝不替代 L1 安全控制，核心工艺参数强制本地处理

4. **务实路径**：四阶段实施（场景验证 → 单场景规模化 → 多场景平台化 → 生态化运营），从高价值场景切入，逐步沉淀共性能力

5. **效益可期**：基于两家企业已有的数字化成果（磷化年省百万级、铝业年省 4000 万），平台化推广后预计可复制至整个磷化工和电解铝行业
